Конвейер: 8 шагов

Сначала дешёвые проверки, потом внешние, потом расчёты и фиксация. При сомнении — не одобрять: лучше NEED_MORE_DATA, чем ошибочный APPROVED.

1. ВалидацияОбязательные поля, возраст 18–70, сумма 10k–1M, срок 3–60. Ошибка — 422, пустое поле — NEED_MORE_DATA.
2. СМЭВPOST /smev/identity, таймаут 3000 мс, один retry через 0,5 с. MISMATCH — отказ, timeout — NEED_MORE_DATA.
3. БКИPOST /bki/score, таймаут 3000 мс. Возвращает score 300–850, delinquency, inquiries_90d.
4. СкорингСумма баллов по 5 признакам, 0–100. При отрицательном итоге — cap до 0.
5. ЛимитыDTI по аннуитету, ставка 18%. Сумма ≤ 10 × доход. Превышение — отказ или снижение суммы.
6. Правила отказа10 правил сверху вниз, первое сработавшее — финальное.
7. РешениеAPPROVED — сумма, срок и ставка 0,18. REFUSED — null и код причины. NEED_MORE_DATA — что дослать.
8. АудитЗапись AuditEvent: 8 полей, append-only, время в UTC.

Формула DTI

monthly_rate = 0,18 / 12 = 0,015
payment = amount × monthly_rate / (1 − (1 + monthly_rate)^(−term))
dti = payment / income — округление до 2 знаков, порог 0,5.

Пример app_0001: платёж ≈ 24 962 ₽, dti = 24 962 / 120 000 ≈ 0,21.

API

GET /health — проверка живости. POST /api/v1/applications — подача заявки, 201 — решение, 422 — ошибка валидации, 409 — дубликат app_id. GET /api/v1/applications/{id}/decision — 200 — решение готово, 404 — не найдена, 425 — решение ещё считается. POST /api/v1/applications/{id}/recalculate — пересчёт, 409 — пересчёт невозможен.

Application

app_id: app_NNNN • client_id: cli_NNNN • passport_hash: 16 hex • age 18–70 • income > 0 • employment: 5 значений • family: single / married / children • amount 10 000–5 000 000 • term 3–60

Decision

app_id • decision: APPROVED / REFUSED / NEED_MORE_DATA / MANUAL_REVIEW • reason • score 0–100 • dti ≥ 0 • amount_approved • term_approved • rate • bki {score 300–850, delinquency} • smev: MATCH / MISMATCH / TIMEOUT / NOT_CALLED

Внешние сервисы — эмуляторы

Реальных БКИ и СМЭВ нет, ответы детерминированные: один и тот же вход — один и тот же ответ. СМЭВ: h = md5(client_id) mod 10; h == 0 → MISMATCH, иначе MATCH. БКИ: h = md5(passport_hash) mod 10; 0–5 → 600 + h×20; 6–8 → 450 + (h−6)×50; 9 → 400, delinquency = true. Если в заявке есть bki_score или smev_status — берутся они. TIMEOUT задаётся значением в CSV, сам эмулятор его не выдаёт.

Сбои: СМЭВ или БКИ не ответили за 3 с после повтора → NEED_MORE_DATA, EXTERNAL_TIMEOUT, скоринг не считается. СМЭВ MISMATCH → БКИ не вызывается. Circuit Breaker, retry с экспоненциальной задержкой только для идемпотентных запросов, повтор через 30 с.

Модель данных

Client — заёмщик, только хэш паспорта (client_id, passport_hash). 1 клиент — много заявок.
Application — заявка: app_id, client_id, product_id, age, income, employment, family, amount, term.
Decision — решение 1:1 к заявке: decision, reason, score, dti, amount_approved, term_approved, rate. До расчёта — 425.

Product — условия: min/max amount и term, rate, min/max age, min_income.
ExternalRequest — обращение к БКИ/СМЭВ: request_id, service, status, latency_ms, result. Обычно 2 на заявку.
AuditEvent — неизменяемая запись, append-only: event_id, app_id, action, decision, reason, score, actor, at (UTC).

В applications.csv 14 колонок: app_id, age, income, employment, family, amount, term, decision, reason, client_id, passport_hash, dti, bki_score, smev_status. Оригиналы паспортов и PAN не хранятся.

Угрозы и контрмеры

U-3 Подделка данных — СМЭВ, сверка дохода с БКИ/ФНС, OTP.
U-4 Обход скоринга — HMAC-подпись ответов, запрет прямого UPDATE для app_user, аудит изменений decision.
U-5 Отсутствие аудита — 8 полей, WORM-хранилище, ретенция 12 мес.
U-6 Таймаут БКИ — Circuit Breaker, fallback NEED_MORE_DATA, не автоматический approve.

Защита данных

PAN — нельзя, только токен или последние 4 цифры. Оригинал паспорта — нельзя, только SHA-256 хэш 16 hex. ФИО, телефон, адрес — можно с TDE-шифрованием, в логах — маскирование: Иванов И.И., +7***123-45-67, i***@example.com. passport_hash не логируется и не возвращается в API. income в логах — ***, в API — только со scope scoring:read. Секреты — Vault / HSM / KMS, ротация: пароли БД 30 дней, HMAC и API-ключи 90 дней, JWT 24 часа. Секреты не коммитятся в Git.
